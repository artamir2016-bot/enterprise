# DevTracker — конфигурация OES для разработки самой платформы

Конфигурация **на самой OES** для ведения разработки форка: багтрекинг + СППР
(требования/планирование) + реестр фич GUI-тестирования. Dogfooding — платформа
трекает собственную разработку.

## Что внутри (`devtracker.json`)

**Перечисления:** `СтатусДефекта`, `Серьёзность`, `СтатусТребования`, `Приоритет`,
`РезультатТеста`.

**Справочник `Компоненты`** (предопределённые): Backend, Frontend, Компилятор,
ДвижокЗапросов, Формы, Дизайнер, Предприятие, ВебКлиент, Отладчик, Тесты, CI.

**Документ `Дефект`** (багтрекинг): Заголовок, Серьёзность, Статус, Компонент,
НайденТестом (→ ТестоваяФича), КоммитФикса; ТЧ `Описание` (строки repro/описания).
Номер+Дата — штатные реквизиты документа.

**Документ `Требование`** (СППР): Заголовок, Приоритет, Статус, Компонент,
ОценкаЧасы; ТЧ `Обоснование`.

**Справочник `ТестоваяФича`** (реестр фич GUI-тестов): Описание, Файл, Требование
(→ связь СППР), ПоследнийРезультат; **ТЧ `Содержимое`** (НомерСтроки, Текст) — для
построчного хранения содержимого `.feature`. Предопределённые элементы заведены по
фактическим фичам из `tools/oes_testrunner/features/`:
`demo_ru`, `managed_form_designer`, `ГруппировкаШаговВидео`.

## Как собрать и загрузить

```bat
set BIN=E:\Projects\OES\build-perf\bin\Release
REM 1) spec .json -> .mcf (бэкенд ibBuildConfigFileFromJsonSpec)
%BIN%\oes_config_gen.exe tools\devtracker\devtracker.json tools\devtracker\devtracker.mcf --verify
REM 2) батч-загрузка в базу (создаёт/обновляет схему БД)
%BIN%\designer.exe /FE:\Projects\OES\testbase\devtracker_base ^
    /LoadCfgE:\Projects\OES\tools\devtracker\devtracker.mcf /UpdateDBCfg
REM 3) работать:
%BIN%\enterprise.exe /FE:\Projects\OES\testbase\devtracker_base
```

Проверено (2026-10-09): генерация + verify-reload OK; батч-загрузка `UpdateDBCfg`
OK; дизайнер показывает дерево (Компоненты / ТестоваяФича / Дефект / Требование),
предприятие открывает списки и формы, предопределённые Компоненты и ТестоваяФича
присутствуют — 0 диагностик.

## Сохранение содержимого файлов фич

Структура `ТестоваяФича.Содержимое` (строка-на-линию) готова под полный текст
`.feature`. Сейчас фичи зарегистрированы как предопределённые элементы (имя +
описание). Построчное наполнение содержимым выполняется через ввод в предприятии
или появится автоматически, когда в скриптовом языке появится чтение файлов
(`ЧтениеТекста`/`TextReader` — пункт T3.3 бэклога апстрим-реимплементации): тогда
процедура-загрузчик прочитает `tools/oes_testrunner/features/*.feature` и заполнит
ТЧ. `devtracker_base` — рабочая база (в git не коммитится, воспроизводима из `.mcf`).
