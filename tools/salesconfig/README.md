# УчётПродаж — тестовая прикладная конфигурация OES (учёт продаж)

Небольшая, но содержательная конфигурация на OES для проверки платформы на
«настоящей» предметной области: справочники, документы с табличными частями и
движениями, регистры сведений и накопления (остатки + обороты), перечисления.

## Состав

**Перечисления:** `ВидЦены` (Закупочная/Оптовая/Розничная),
`СтатусЗаказа` (Новый/ВРаботе/Выполнен/Отменён).

**Справочники:** `Организации`, `Склады`, `ЕдиницыИзмерения`, `Номенклатура`
(Артикул, ЕдиницаИзмерения → ref, Услуга), `Контрагенты` (ИНН, Телефон).
Есть предопределённые элементы (ОсновнаяОрганизация, ОсновнойСклад, шт/кг).

**Регистр сведений:** `ЦеныНоменклатуры` — измерения Номенклатура + ВидЦены,
ресурс Цена.

**Регистры накопления:**
- `ОстаткиТоваров` — **остатки** (balance): Номенклатура × Склад → Количество.
- `Продажи` — **обороты** (turnover): Номенклатура × Контрагент × Организация →
  Количество, Сумма, Себестоимость.
- `ВзаиморасчётыСКонтрагентами` — **остатки** (balance): Контрагент × Организация → Сумма.

**Документы** (с табличной частью `Товары` где применимо и движениями по регистрам):
- `ПоступлениеТоваров` → ОстаткиТоваров, ВзаиморасчётыСКонтрагентами.
- `РеализацияТоваров` → ОстаткиТоваров, Продажи, ВзаиморасчётыСКонтрагентами.
- `ЗаказПокупателя` (план, без движений; Статус → ref Enum).
- `ПоступлениеОплаты` → ВзаиморасчётыСКонтрагентами.

**Роли:** `ПолныеПрава` (структурная, права — отдельная итерация).

## Сборка и загрузка

```bat
set BIN=E:\Projects\OES\build-perf\bin\Release
set SC=E:\Projects\OES\tools\salesconfig

REM 1) спека JSON -> .mcf (с самопроверкой перезагрузки)
%BIN%\oes_config_gen.exe %SC%\salesconfig.json %SC%\salesconfig.mcf --verify

REM 2) загрузить .mcf в свежую файловую базу и применить к БД (headless batch)
%BIN%\designer.exe /F<папка_базы> /LoadCfg%SC%\salesconfig.mcf /UpdateDBCfg /Out%SC%\_batch.log
```

Рабочая тестовая база: `testbase\salesconfig_base` (не в git). Firebird-файловая
база — один процесс: держи её открытой ЛИБО в предприятии/дизайнере, ЛИБО в
oes_query, не одновременно.

## Формат спеки — важное

Тип типизированного дочернего (реквизит / измерение / ресурс / реквизит ТЧ)
задаётся **плоско**, квалификаторы — соседние ключи, НЕ вложенные под `type`:

```json
{ "name": "Цена",  "type": "Number", "precision": 15, "scale": 2 }
{ "name": "Товар", "type": "ref",    "refs": ["Catalog.Номенклатура"] }
{ "name": "Код",   "type": "String", "length": 9 }
```

Вложенная форма (`"type": { "type": "Number", … }`) — ошибка (генератор её
отклоняет с понятным сообщением): иначе тип молча вырождается в String, и у
балансового регистра накопления числовой ресурс становится строковым — тогда
триггер сопровождения итогов падает на «Strings cannot be negated».

Тип регистра накопления: `"registerType": "balance"` (остатки, по умолчанию) или
`"turnover"` (обороты).
